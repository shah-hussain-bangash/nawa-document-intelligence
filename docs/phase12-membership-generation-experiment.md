# Synthetic membership-generation experiment

This integration draft adds database-assigned membership, identity and tenant generations and binds a process-local session to the generations returned by the server-side membership lookup. Changing a membership's active state or role, changing an identity or tenant's active state, or recreating the corresponding record assigns a new generation. On the next protected request, a mismatched generation invalidates the old session; a newly authenticated session can use the current generations.

Migrations `005_membership_generation.sql` and `006_identity_tenant_generation.sql` are new and leave previous migration files and their checksums unchanged. The tests apply them only to disposable synthetic databases, including upgrades from prior schemas. No migration of existing NAWA workspaces, uploads or databases is authorized or performed by this experiment.

This is not a production revocation guarantee. Provider-side disablement and account sessions are not synchronized. A stale database restore can reinstate old generations: a still-running process may accept an unexpired session whose intervening revocation it never observed. A disposable test characterizes this risk and shows that replacing the process-local session store rejects its old token; this is not an automated or distributed recovery control. A database restore can also rewind sequence state, and privileged database users can alter triggers or data. A request can still race with a change after its last authorization check, sessions remain process-local, and database permissions, distributed invalidation, coordinated backup and recovery, and independent security review remain open. The browser test uses a disposable CI-only certificate and synthetic identities.
