The browser uploads an Arabic TXT fixture, rejects a fabricated excerpt, accepts a correction referencing retained text, obtains a separate reviewer's approval and compares it with an approved English quotation. Text matching does not prove a correction is semantically correct, and this is not an OCR accuracy evaluation. Synthetic migrations assign membership, local identity and tenant generations. A stale-backup test showed that an unpaused process can accept an old session against a pre-change restore. An opt-in single-process gate on the draft protected handler rejects new GET and POST requests and waits for active enrolled requests before a simulated restore; the running portal and background workers are not configured with it, and restore is a stub. A separate ordering experiment restores a disposable database using trusted callback signals. This is not automated recovery: all relevant work and processes require coordination and controlled release. Provider-side revocation and company-trusted certificates remain open. These synthetic checks do not prove production isolation or authorize migration of an existing database. This is a test draft, not a merged release; reconcile changes if #9 or #10 is applied upstream so they are not duplicated.

Withdrawal affects only this experimental retrieval path, not the portal or other services. A new synthetic migration is included for review; existing databases have not been migrated. There is no authenticated retrieval endpoint or per-document ACL; database and file reads are not atomic, and changes after the final read can race the response. This does not establish production isolation.

Review PR dependencies and migrations and demonstrate isolated recovery. Keep existing databases and uploads unchanged during testing.
