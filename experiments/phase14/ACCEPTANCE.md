checkpoint maps the Phase 14 criteria in the supplied office implementation
playbook to the evidence available in this draft. It does not certify the
system or claim that later project phases are complete.

## Remaining work

1. Develop and independently review a larger bilingual evaluation set with
   held-out paraphrases, unanswerable questions, contradictory claims,
   version/deletion cases and malicious-source scenarios. Agree on measurable
   thresholds before using it as an acceptance gate.
2. Design and assess a safe evidence and abstention workflow. Preserve human
   decisions; do not claim that similarity, exact matching or a model verdict
   proves a generated claim.
3. Complete the Phase 12/13 prerequisites and security review. Define
   authenticated retrieval, approved document lifecycle/deletion and vector
   invalidation, audit and operational recovery before integration.
4. Re-run the comparison on the reviewed set, evaluate quality, latency and
   resource cost, and record the exact passing revision and unresolved risks.

No delivery date can be determined from the current evidence. This draft is
not connected to the running portal, and no production data was used.

An initial blinded review packet can be generated by
`make_review_packet.py`: it separates reviewer files from the local reference
key and contains 36 synthetic retrieval questions, 10 authorized passages
and 28 claim/evidence examples. This merely prepares the review; no independent
review or label adjudication has yet occurred. The underlying cases are the
same hand-authored development set, not a newly collected or held-out set.
The comparison tool reports disagreements and leaves blank or uncertain
judgments uncounted; reference-label agreement is not ground truth.
The additional 20-question retrieval set has its own separate blinded packet.
It is not independently reviewed until an independent reviewer completes it
and any label disagreements are adjudicated.

The fixed bundled-PDF CLI is a synthetic review demonstration, not an
authenticated portal, an answer generator, or evidence that Gate G14 passed.
Its Arabic option uses one mixed Arabic–English selectable-text fixture;
normalized Arabic output must be checked against the original PDF.
The separate Arabic-label TXT demonstration uses actual TXT line references;
it does not establish Arabic-only PDF or OCR support.
One separately generated local Arabic-label PDF revealed a currency-order
failure. The Phase 14 draft now applies a narrow AED normalization in the
separate Phase 3 PDF extractor, and an isolated local test extracted its
synthetic total. Separately, the draft intake worker supports the exact
bundled mixed Arabic–English fixture through a hash-specific route to that
extractor. The generated Arabic-label PDF is not in that route. This does not
establish OCR or real-world Arabic PDF quality.
